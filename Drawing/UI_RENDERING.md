# KL 与伊蕾娜共用：UI 分辨率与栅格清晰度

本经验由两个项目的根目录 `AGENTS.md` 引用，统一在此维护。适用于文字、线稿图标、星芒、细线、圆点与装饰圆环等 UI 元素的新增和清晰度修复。

来源：2026-11-04 伊蕾娜技能面板在笔记本屏幕上的修复。共用的是诊断方法、资源处理和验收方式；具体图集、字号范围与加载实现仍由各界面按需求选择。像素画应保留其有意设计的像素边缘。

## 1. 先确定问题发生在哪一层

区分布局适配、字体可读性和栅格失真：窗口越界、字号过小、细线断裂、星芒发糊需要不同的处理。先记录实际游戏窗口像素尺寸、游戏 UI 缩放、面板自身适配倍率和最终绘制矩阵；显示器标称分辨率不能单独说明元素占多少屏幕像素。

在无旋转、等比缩放的 UI 中：

```text
实际像素尺寸 = 设计尺寸 × 面板适配倍率 × UI 缩放倍率
```

涉及额外变换或 RenderTarget 时，以最终到屏幕的完整变换为准，避免漏算或重复乘 UI 缩放。`M11` 作为倍率只适用于相应的轴对齐、等比变换；旋转或非等比变换需另行计算。

先截取原生分辨率下的局部，检查透明度、源贴图尺寸、实际字号、采样器和像素原点。仅增加贴图分辨率、放大整个面板或统一加锐，都不能保证解决缩小后的失真。

## 2. 细线图标与星芒：保留缩小后的像素覆盖率

- 当线稿从大图缩到几十像素时，使用离线面积滤波或适当的超采样降采样，保留细线覆盖目标像素的比例。只有双线性采样的大比例缩小仍可能漏掉笔画。
- 按元素实际使用的屏幕尺寸准备图集层级。特别小的星形可采用更密的整数像素层级，减少在 4px、8px 等相距过大的贴图之间反复缩放。
- 静态小图标可将目标尺寸取整，并按尺寸奇偶对齐边界；对齐发生在设备像素空间，随后转换回绘制空间。运动、呼吸和旋转元素须额外检查取整造成的跳动，不能无条件套用静态对齐。
- 图集切片之间保留透明间隔，细线和圆点周围保留采样边距，避免采到相邻图案或将纹理边缘拉成方块。
- 根据源资源的 Alpha 约定进行滤波与保存。已经预乘的 RGBA 要一起处理；保留原图灰色填充与颜色层次。将所有 RGB 替换成 Alpha 只适合确认为白色的遮罩。

案例：技能面板的帽子从 156px 贴图直接缩到约 40px 后出现断线，新增接近显示尺寸的滤波层级后改善；星芒使用独立密集图集，保留其他消费者使用的原图集。

### 资源层级按显示尺寸决定，不固定制作三套屏幕版本

资源数量由元素实际占用的屏幕像素范围及视觉检查决定，不按“1K / 2K / 4K”标签硬分三套。举例：设计宽 40px、没有额外面板缩放的图标，在 100% / 150% / 200% UI 缩放下分别占 40 / 60 / 80 个屏幕像素；高分辨率下若仍只占 40px，也不需要因为屏幕更大而换成 80px 资源。

仅把 40px 源图拉到 80px，点采样会放大像素块，线性采样会插值平滑，但无法恢复源图未记录的轮廓细节。资源准备优先保留一份足够大的母版或矢量源，再从该母版派生所需尺寸；不要从已经缩小的版本反向放大制作高分辨率版本。

- 普通插画或低频装饰可先用一份足够大的源图及合适的缩小过滤，经实际显示检查后决定是否需要更多层级。
- 跨尺寸显示的位图可使用预先生成的 mipmap 或手动选取图集层级；必须确认实际资源加载与采样路径支持并使用这些层级。
- 帽子细线、小星芒和小字号文字按实际像素需求补充更密的层级，通常无法只靠三档屏幕分类覆盖。
- 可用几何或 SDF 表达的简单形状，可按目标像素尺寸求覆盖率；此类实现也要检查边缘抗锯齿和小尺寸辨识度。

“一份创作母版”与“运行时只有一张小贴图”是不同的选择。多尺寸资源可由工具统一生成并装入图集，无须手工维护三套独立美术。高分辨率的选择规则同样需要适当的大尺寸来源，不能据此承诺任意倍率下都无损清晰。

## 3. 字体：字号、字形度量和像素对齐一起处理

- 以屏幕实际字号选字形资源，覆盖目标 UI 缩放产生的中间字号。检查缺失字号、异步资源未就绪、缺字等情况是否触发母版回退，避免同一行中的片段采用不同的缩放路径而不自知。
- 精确字号的烘焙字体也需要目视检查。若笔画阶梯明显，可从已有母版离线积分像素覆盖率，保留足够的 Alpha 精度；实际效果由原生尺寸对比决定，不能只凭“按 1:1 绘制”判定清晰。
- 测量、换行、截断、富文本排版和绘制使用同一套字形度量。字号或有效缩放改变时，重新计算相关布局与术语命中区域。
- 将静态文字的绘制原点对齐设备像素，连同字形偏移和绘制倍率一起检查。轮廓平滑与行内基线、字距稳定同样重要。
- 保留缺字和超出字号范围的可用回退。新增本地化文字、术语或动态物品名称后，检查实际字符集并按需重建资源；不能把这次技能面板的字符子集当作所有 UI 的完整字库。
- 字库与图集的尺寸、打包体积、显存占用都纳入实现选择，按需缓存和加载。通用经验不要求每个窗口复制一整套字体资源。

案例：本次技能面板使用无损 8-bit Alpha 字形图集及配套度量，同时修改正文与术语说明的测量和绘制。2026-11-04 清理前核对 KL 与伊蕾娜的正式源码，旧小字号加载器的调用方仅为新技能面板的回退；其他界面使用原始母版。清理后面板缺字或超出字号范围直接回退母版，旧加载器已移除。后续清理仍应重新检索当时的调用方。

已删除旧的小字号 XNB 共 54 份，磁盘合计 7,154,650 字节（约 6.82 MiB，非显存占用或最终模组压缩体积）。生成字符集已保存为独立的 `Tools/ConstellationRasterChecks/charsets.json`，回退、生成及预览入口均不再依赖旧副本。原始母版仍被多个界面及新资源生成流程使用，需要保留。精简同类资源时先固定可维护的字符清单和迁移依赖，验证可重新生成后再删除；多个界面复用新方案时，优先整合共用的加载与资源管理。

后续炼金手记也复用上述同一批字体和装饰图集。对于倾斜、缩放的卡片，文字布局按根 UI 尺度选择字形，额外变换只作用于绘制，避免卡片动画反复改变换行。极小图标需要时制作保持原轮廓的简化细节版本：研习点书本的 13px / 15px 版本减少页内细线，27px 页头继续保留完整装饰；多尺寸滤波不能代替小尺寸辨识度检查。

## 4. 点线和圆环：装饰密度随屏幕尺寸调整

- 圆点数量、间隔和最小可见宽度依据实际屏幕周长或线段长度确定。固定的大量线段在小圆环上会变成亚像素碎片，应为点与间隔保留足够空间。
- 小尺寸应优先保住可辨认的形状；点数上限、间距与描边宽度按具体设计验收，不照搬某个界面的固定常数。
- 旋转的单像素实心矩形会产生硬边台阶。按需要使用带透明边缘的预制笔画遮罩或合适的抗锯齿绘制路径，同时检查亮度和线宽是否改变。

连续实线圆环还要检查描边跨越绘制分支阈值的情况：设计线宽 1.2px 乘提示自身 1.35 倍即为 1.62 屏幕像素，若抗锯齿只覆盖 ≤1.5px，就会在正常大小或弹出缩放中突然变硬。大量短矩形的接缝和重叠不能靠增加分段消除。正圆可用解析距离计算内外边缘的像素覆盖率，内外覆盖相减以保留亚像素描边能量；动态半径属于 Shader 绘制，不必离线生成所有动画尺寸。保持描边中心半径和连续位置，并检查切换 Effect 后的矩阵、裁剪、采样及后续绘制。回归应包含阈值两侧、独立面积积分参考和旧画法反例；伊蕾娜的具体入口与验证范围见 `Tools/ConstellationRasterChecks/README.md`。

案例：直径约 8px 的“未显现”标记原先容纳 40 段短线，改为按屏幕周长排列可分辨的圆点。增加几何细分本身无法修复这种密度问题。

静态重复标记还需检查同一行内的像素覆盖是否一致：小数间距会让每个标记落在不同子像素位置。可在最终设备空间统一标记尺寸、首个边界及整数像素间距，再转换回绘制空间；不要用此规则替代运动元素的连续位置。实心与空心版本应共用外轮廓，描边向内保留，避免空心版视觉上额外膨胀。炼金研究收录的回归直接比较 22 个位置，并确认旧绘法能触发差异。

## 5. 接入正式渲染时保持边界清楚

- 为自己的绘制范围显式选择适合资源的采样器。若切换 SpriteBatch，结束后恢复调用方状态；核对变换矩阵、混合、裁剪和 RenderTarget，避免影响其他 UI。
- 清晰度修复沿用正确的布局与命中坐标。若确实调整布局，则同时验证点击、悬停、滚动和拖拽坐标。
- 正式游戏中加载预先制作并打包的固定贴图。原型与离线预览允许生成纹理；接入前导出正式资源，并移除游戏初始化或绘制阶段的固定纹理生成，包括“一次生成”和“缺图时生成”。依赖当前画面的动态 RenderTarget 与动态 Shader 绘制另行处理。
- 生成器和验证工具放在构建、打包排除的目录。PNG、图集索引及字形度量放在正式资源目录并一起打包，保留可复现的生成入口。
- 热路径中复用缓存；选图集层级不需要每帧排序、分配列表或重建纹理。

## 6. 验证与交付

涉及清晰度或缩放的改动，至少验证 1K 原生尺寸、一个非整数有效缩放以及支持的高分辨率配置。以下是本次可复用的验证组合，具体取舍按界面支持范围说明：

| 窗口尺寸 | 游戏 UI 缩放 | 主要检查 |
| --- | --- | --- |
| 1366×768 | 100% | 面板被动缩小后的细节和裁剪 |
| 1864×977 | 125% | 笔记本窗口与面板适配叠加 |
| 1920×1080 | 100%、112.5%、125%、150% | 基准与中间倍率、像素原点 |
| 2560×1440 | 150% | 高分辨率资源选择 |
| 3840×2160 | 200% | 大尺寸、字号回退与纹理边界 |

导出不经二次缩放的截图，在查看器 100% 下判断可读性；局部放大用于定位像素缺陷，并明确标注放大倍数。修改前后保持相同布局、尺寸、颜色和缩放，便于比较。

优先重放正式绘制、字体与富文本代码，并包含真实非整数矩阵和小数原点。既看局部细节，也看整页的长描述换行、标题和按钮、术语提示、裁剪及滚动后的状态。改动涉及的中英文和动态内容均应覆盖。

回归检查应能暴露旧问题。例如本次标题在 100% / 112.5% 下使用原生字形后，PointClamp 与 LinearClamp 的 RGB 差异不超过 2；旧母版缩小路径不能通过此检查。这项性质仅适用于该原生字形路径，不能要求所有抗锯齿贴图在两种采样器下相同。

分别记录资源检查、离线渲染、完整构建和游戏内验证的结果。离线预览通过只证明已覆盖的场景，不等于已加载进游戏，也不能推断任意分辨率、缩放或所有 UI 都已经通过。
