# 共用 Bloom 的采样与分辨率

2026-11-05 修复：伊蕾娜在 1920×1080 报告火焰光晕格子、多重射击十字星条带和细拖尾失光。通过正式绘制与 KL Bloom 离线重放复现。

## 约定

- 捕获阶段遵守消费者的材质和采样；后处理处理连续光能，固定使用 LinearClamp，不能继承 `Main.DefaultSamplerState`。原版场景目标路径会选 PointClamp，而直接画屏路径通常为 LinearClamp。
- s0 与用于重建/合成的 s1 都要设置；完成后恢复调用方的辅助采样器和批次状态。只给主贴图设线性过滤不能保证多输入 pass 正确。
- 先结束批次、绑定目标，再 Begin，让投影使用实际目标 Viewport；每一级明确把完整源图绘到完整目标矩形。不要依赖 Begin 后切换目标产生的隐含比例；奇数尺寸、逻辑场景与 backbuffer 大小不一致时尤其危险。
- 模糊核步长以**被采样源纹理**的宽高求倒数。旧实现的 `targetSize / 4` 在降低一级时跨过 8 个源像素，点采样下形成重复亮点和格子，细线还可能被漏采。连续滤波后再缩小，重建时线性放大并叠加同级细节。
- 单次写满、包含已经计算好混合结果的模糊 pass 使用 Opaque；背景/本体合成保留 AlphaBlend，光晕不应增加场景遮挡。不得为了让细线看见而同时改变全局 HDR、描边或拖尾几何宽度。
- 固定纹理预制约定不变；Bloom 依赖当前画面，使用动态 RenderTarget。此次未增加目标数量或分辨率，也未新增纹理或改变 Shader 字节码。

## 验证

入口位于相邻伊蕾娜仓库：`Tools/BloomResolutionPreview`（实际星/火/拖尾、多分辨率、采样一致性、光点相位、尺寸不一致），`Tools/BloomBackbufferPreview`（直接画屏、目标、批次、异常、生命周期），`Tools/LineSparklePreview` 与 `Tools/FireLaserPreview`（正式消费者）。具体命令、基线版本、数字和未通过的旧工具见前者 README。

不能只看放大的游戏截图，也不能把“能出光”当作通过：分别看原生局部的格子、条带、细线外的柔光，以及移动时的亮度和形状稳定性。离线通过、源码编译、完整打包和游戏内重载分别报告。此修复只覆盖共用 Bloom 后处理；源 Shader/贴图本身的锯齿、低于提亮阈值的素材和有意设计的几何缩放，需要另行诊断。
