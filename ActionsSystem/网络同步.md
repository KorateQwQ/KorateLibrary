# 网络同步

## 启动动作的消息路径

`ActionModPlayer.StartAction` 的参数是动作实例、是否中断旧动作和起始旋转角。它先在调用端执行 `StartActionLocal`，然后发送：

```text
RPC("StartActionById", [animActionId, interruptCurrentAction, rotation], ClientToAll)
```

KL 的 `KLModPlayer.RPC` 将当前 `ModPlayer` 的完整类型名和 `Player.whoAmI` 作为 RPC 目标。动作 ID 由 `AnimAction.TypeId` 提供。

在单人模式，`KLNetModule.RPC` 直接反射调用目标方法，不创建网络包。在多人模式，RPC 包包含消息类型、发送模式、目标类型名、实例 ID、实例 owner、方法名、参数数量及带类型标记的参数。`StartActionById` 收到 ID 后通过 `AnimActionRegistry.TryCreate` 创建新的无参动作实例，再调用本地启动逻辑。

`ClientToAll` 的典型流程如下：

```text
发起客户端：本地 StartActionLocal
        -> 发包 ClientToAll
服务器：解析玩家实例 -> 调用 StartActionById
        -> 转发 ServerToClients（排除原发起客户端）
其他客户端：解析同一个玩家实例 -> 调用 StartActionById
```

这样每个端都以同一动作类型和同一开始帧推进，而不是逐帧发送动作状态。

接收端如果发现当前动作已经是相同 ID 且 elapsed 仍为 0，会忽略这次重复启动，避免同一广播在本地重置动作。

## 同步前提

- 所有端必须加载相同的动作类型集合。注册表按 `FullName` 的序号排序后分配 ID，但 ID 不是持久协议；增删动作类型或使用不同程序集版本，都可能导致同一个 ID 对应不同动作。
- 动作构造函数必须是无参构造函数，因为接收端只收到 ID，不会收到构造参数。
- `rotation` 只是启动时同步的一次浮点参数；后续动作逻辑不会自动同步其它自定义字段。
- 每个端独立推进本地帧计数，网络层不发送每帧确认、回滚或纠正。如果客户端丢包、延迟或端上逻辑耗时，动作表现可能出现帧偏差。

## 权威性边界

动作节点会在所有拥有该玩家实例的端执行，但部分内置节点主动限制为本地玩家：

- `CallbackActionNode` 仅当 `actionPlayer.Player == Main.LocalPlayer` 执行。
- `ShootActionNode` 最终由 `ShootFromAction` 检查 `player.whoAmI == Main.myPlayer`，只由拥有者生成弹幕。
- `ShootActionNode` 的 `configureProjectile` 回调在拥有者端执行，顺序位于弹幕 `OnSpawn` 之后、首个 `SyncProjectile` 包发送之前；回调设置的初始状态会随该首包传播。

因此动作本身只同步“播放意图”和表现时间轴；伤害、生成物等游戏状态应由拥有者生成后使用 Terraria 的实体同步，或由服务器 RPC 明确执行。不要把只在客户端运行的回调当作服务器权威判定。

## 参数限制与安全注意

KL RPC 的通用参数序列化支持 `int`、`float`、`double`、`bool`、`string`、`byte`、`short`、`long`、`Vector2`、`Color`、`NPC`、`Player`、`Projectile` 和 `List<int>`。动作启动当前只使用 `int`、`bool`、`float`。

RPC 通过类型名、实例 ID 和反射方法名定位目标。扩展动作时应保持 RPC 方法参数签名明确、可序列化，并在方法内部再次验证玩家状态、权限和输入来源。
