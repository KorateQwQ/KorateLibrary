# 扩展指南

## 1. 创建动作类型

继承 `AnimAction`，提供公开无参构造函数，在构造函数中指定默认总帧数并添加节点。需要动态时长时，可额外提供带 `totalFrame` 的构造函数；动作启动时该时长会通过 RPC 同步到其他端。动作类型会在 KL 加载时自动扫描，不需要手动调用注册 API。

```csharp
public sealed class ExampleCast : AnimAction
{
    public ExampleCast() : this(45)
    {
    }

    public ExampleCast(int totalFrame) : base(totalFrame)
    {
        AddNode(new ArmActionNode(
            0, 12,
            ActionArmType.Front,
            Player.CompositeArmStretchAmount.Quarter,
            Player.CompositeArmStretchAmount.Full,
            -0.8f, 0.2f));

        AddNode(new CallbackActionNode(20, (actionPlayer, frame, progress) =>
        {
            // 仅本机执行：播放音效或生成本地粒子。
        }));
    }

    public override void OnStart(ActionModPlayer actionPlayer)
    {
        // 初始化动作专用状态。
    }

    public override void OnFinish(ActionModPlayer actionPlayer)
    {
        // 自然结束后的清理。
    }

    public override void OnInterrupt(ActionModPlayer actionPlayer)
    {
        // 被打断后的清理；不要假设会经过 OnFinish。
    }
}
```

动作需要在某一帧等待玩家输入时，可以定义自动保持点：

```csharp
public override bool IsAutomaticHoldPoint(ActionModPlayer actionPlayer, int actionFrame)
{
    return actionFrame == 30;
}

public override bool ShouldContinueHolding(ActionModPlayer actionPlayer, int actionFrame)
{
    return Main.mouseLeft;
}

public override void OnHoldUpdate(ActionModPlayer actionPlayer, int actionFrame, int holdTime)
{
    // 保持姿态或物品状态；普通时间轴节点在这里不会重复执行。
}
```

只有动作拥有者会调用 `ShouldContinueHolding`；解除结果由 `ActionModPlayer` 同步。也可以由弹幕等外部对象调用 `SetCurrentActionHold(true/false)` 主动控制当前动作的保持状态。

带参数构造函数只应在动作启动前决定总时长；动作开始后不要修改 `TotalFrame`。如果节点时间轴也需要随时长变化，应在构造函数中根据 `totalFrame` 计算节点帧，而不是继续使用固定帧值。

启动动作：

```csharp
player.GetModPlayer<ActionModPlayer>()
    .StartAction(new ExampleCast(), interruptCurrentAction: true, rotation: player.fullRotation);
```

KL 自身加载时会扫描本 Mod 程序集中的动作类型。若动作定义在其他 Mod 中，可在该 Mod 的加载阶段显式调用：

```csharp
AnimActionRegistry.RegisterFromMod(this);
```

也可以调用 `AnimActionRegistry.Register(type)` 注册单个具体类型；重复注册同一类型会返回已有 ID。两种注册方式都要求类型继承 `AnimAction`、非抽象并拥有公开无参构造函数。

## 2. 添加自定义节点

继承 `ActionNode(startFrame, endFrame)`。在 `Update` 中编写逻辑，在 `ApplyFrameEffects` 中编写每帧玩家表现，在 `Draw` 中根据 `drawLayerType` 绘制。使用基类的 `Lerp` 和 `Clamp01`，不要重复实现进度限制。

```csharp
public sealed class ScaleActionNode : ActionNode
{
    private readonly float from;
    private readonly float to;

    public ScaleActionNode(int start, int end, float from, float to)
        : base(start, end)
    {
        this.from = from;
        this.to = to;
    }

    public override void ApplyFrameEffects(ActionModPlayer actionPlayer, int frame, float progress)
    {
        actionPlayer.Player.fullRotation = Lerp(from, to, progress);
    }
}
```

节点区间可以重叠；同一帧按添加顺序执行。若多个节点修改同一字段，应在动作中明确顺序，或在自定义动作里增加冲突规则。

## 3. 添加单帧事件或射击

单帧事件使用 `CallbackActionNode(frame, callback)`。需要生成弹幕时使用 `ShootActionNode`，提供弹幕类型、位置函数、伤害、击退和速度函数。位置和速度函数会在触发帧才计算，适合读取当时的玩家朝向和鼠标状态；生成仍只会发生在弹幕拥有者本机。

`ShootActionNode` 还可以接收可选的 `configureProjectile` 回调，用于在弹幕生成后配置自定义状态：

```csharp
new ShootActionNode(
    1,
    projectileType,
    player => position,
    damage,
    knockback,
    player => velocity,
    projectile =>
    {
        if (projectile.ModProjectile is MyProjectile myProjectile)
            myProjectile.Setup(targetPosition);
    });
```

回调执行顺序为：初始化弹幕 -> `OnSpawn` -> `configureProjectile` -> 发送首个网络同步包。因此，配置回调适合设置需要随首包同步的 `ai` 或自定义字段；它仍然只在弹幕拥有者本机执行。

若事件需要服务器权威处理，不要直接依赖 `CallbackActionNode`。可以：

1. 在拥有者端验证输入并发送一个专用 RPC。
2. 在服务器端的方法中再次验证玩家状态和参数。
3. 由服务器生成或广播实际游戏实体。

## 4. 使用动作监听器

```csharp
FrameUpdateListener = (player, frame, progress) =>
{
    // 每帧、节点之前执行。
};

PreNodeUpdateListener = (player, node, frame, progress) =>
{
    // 返回 false 可临时跳过某个节点。
    return !player.Player.dead;
};
```

监听器属于动作实例本地状态，不会通过网络传输。接收端由无参构造函数重新建立监听器，因此监听器中不要捕获无法在各端重建的运行时对象。

## 5. 添加自定义绘制

重写动作或节点的 `Draw`，并根据 `ActionDrawLayerType` 选择绘制内容。系统已经注册 `UnderPlayer`、`UnderArm`、`OverArm`、`OverPlayer` 四层；通常不需要再写 `PlayerDrawLayer`。绘制代码应只影响 `PlayerDrawSet`，不要在绘制回调中推进动作状态或生成游戏实体。

## 调试清单

- 收到未知 ID：检查所有端的 KL/Mod 程序集版本和动作类型集合。
- 动作无法启动：确认类型非抽象、继承 `AnimAction`、存在公开无参构造函数且总帧数大于 0。
- 节点异常：检查 `endFrame > startFrame` 且 `endFrame <= TotalFrame`。
- 表现被覆盖：检查同一帧重叠节点的添加顺序，以及 `FrameEffects` 与 `Update` 对同一玩家字段的写入。
